The first release candidate for v0.10.0. Cause investigation gets more trustworthy: remediation is checked against the current source of the tested branch, line-ranged source citations use exact coordinates, and the Investigate cause panel leads with cross-build evidence. Two layout defects are fixed, and diagnostic-authoring reports and the published verification procedures stop reporting success over a failure.

`v0.9.0` never shipped a stable release. Its release candidates have been removed, and the version line continues here.

Upgrading the deployed engine from the last `v0.9.0` candidate needs no project or deployment configuration change and forces no re-analysis. The critique contract stays at 18, so cached analyses are reused. Benchmark input manifests do need the changes listed under Breaking.

## Changed

- **Cause chat checks proposed remediation against current source.** Historical build and source evidence is preserved, while remediation is checked against the current immutable tip of the tested branch. A proposed revision with no current-source evidence stays inconclusive, and prepared cause findings keep historical source access without refreshing the branch. Exact JUnit fixes verify candidate paths and findings against current tested-branch source instead of requiring byte-for-byte equality with historical files. This does not add automatic fixed-status detection.
- **The Investigate cause panel leads with cross-build evidence** and offers a question for identifying the code associated with a failure.

## Fixed

- **Line-ranged source citations use exact repository coordinates.** The analysis model previously had to guess line numbers, so valid citations were rejected for naming the wrong lines. Source file reads now return authoritative ranges. Quote-only citations, which carry no line coordinates, are unchanged.
- **Drafting a multiline question no longer moves the causal group.** Typing in the Investigate cause composer made the surrounding group jump as the composer grew. The panel now stays put while drafting and absorbs composer growth inside the scrollable transcript.
- **Desktop job-detail headers right-align the status label** instead of crowding it beside the job title. The stacked mobile layout is unchanged.
- Diagnostic-authoring reports reject duplicate dashboard trial IDs instead of accepting them after deduplication.
- The published Kubernetes verification and CLI-download procedures propagate failed commands instead of letting a later command report success for the whole procedure.

## Breaking

- Benchmark input manifests require format version 6 and no longer accept `allow_unavailable`. The `citation_policy_unavailable` outcome and the `unavailable_cooldown_hit` metric are removed. These affect the separate benchmark module only.
- Onboarding plans no longer accept the unused `failure_stage`, `failure_category`, and `failure_action` prompt fields. Valid generated plans already omitted them, and the plan schema version and the ordinary AI cache format are unchanged.
