Mostly internal cleanup, plus a release process that can no longer publish the kinds of broken releases this repository has actually produced. Maintainers can attempt a fix on failures the automatic path declines, chat-to-Fix proposals survive the conversation that created them, and the engine and Fix executor images pick up dependency fixes.

Upgrading the deployed engine forces no re-analysis. The critique contract stays at 18, so cached analyses are reused. Several private state formats do reset, and building locally now needs Go 1.26.8; both are listed under Breaking.

## Changed

- **A fix can now be attempted on a failure the automatic path would decline.** Manual requests previously inherited the strict eligibility and preverification rules, so a failure classified as transient, or one with low confidence, incomplete remediation, or no verified citations, could not be investigated at all. The coding agent now works from whatever failure context exists and keeps the uncertainty as warnings. Automatic eligibility, issue eligibility, repository and patch safeguards, and explicit pull request confirmation are unchanged.
- **Chat-to-Fix proposals no longer depend on the conversation that created them.** Each action retains its own selected finding, evidence qualifications, and failure and source bindings, so letting a chat expire or deleting it no longer revokes an admitted Fix, and a pending proposal no longer blocks deletion. Cancel a proposal explicitly instead. The cause, JUnit, repository, branch, and generation-base checks still run before one can be confirmed.
- **Releases are cut by a validated workflow rather than by hand.** The new Release tag workflow refuses to tag unless the version is well formed, its notes exist and are indexed in `CHANGELOG.md` under that exact tag, the version moves the line forward, neither tag already exists, the checkout is the reviewed tip of `main`, and the Go module mirror is not already serving that version. It then pushes both tags atomically, so a release can no longer ship with a missing `backend/` module tag. It pushes with a GitHub App token, because tags pushed with the default `GITHUB_TOKEN` do not trigger publication, and fails closed when that App is not configured.
- **GitHub Releases show the curated notes.** The release body is now `changelog/<tag>.md` instead of a generated commit list, and publishing fails when those notes are missing, empty, or not indexed under the tag being released. Because the notes are published verbatim, links in them must be tag-pinned absolute URLs.
- **A tag that moves the version line backward is rejected.** Comparison is by semantic precedence, so a prerelease sorts below the release it leads to and `beta` sorts below `rc`. The check runs before module-tag repair and before the gate that authorizes version-tagged images, so a backward tag publishes nothing at all.

## Fixed

- Signed-out pull request and shared-failure pages show a sign-in prompt instead of unauthorized investigation errors. Protected reads and controls wait for operator authentication, and signing out clears privileged investigation state.
- Fetch progress no longer reports zero reuse while actually reusing analyses. Its counters came from a retired execution path; it now reports measured analysis states, and an analysis cancelled before it starts is no longer counted twice.
- The engine and Fix executor images include fixes for known Go and container dependency vulnerabilities.

## Breaking

- Building locally requires Go 1.26.8 or later.
- The fetch-status API drops the obsolete analysis task, reuse, cache-disposition, and result-retrieval fields. Private status schema 14 and history schema 6 replace the previous formats with no migration: status is recreated on the next fetch pass and history starts over with newly finished passes. Analysis caches and action state are untouched.
- The unused `chat_fix_min_confidence` capability field is removed. Saved exact-analysis fix previews from earlier versions must be regenerated, as must exact-JUnit previews that lack a complete action-owned handoff. Confirmed receipts and unknown-write reconciliation remain recoverable.
- Recovering a missing `backend/` module tag on an older published release now requires `RELEASE_ALLOW_BACKWARD=true` together with `RELEASE_TAGS_ONLY=true`. Publishing a patch for an older major is not supported by the release automation.
