The third release candidate for v0.10.0 retains operator chat findings across live-session expiry and analysis refreshes, fixes incomplete pull request triage coverage, and adds signed build provenance to published artifacts.

These notes cover changes since v0.10.0-rc.2. Upgrading forces no re-analysis, but changes private chat storage and its rollback procedure as described under Breaking. This is a pre-release and does not advance the stable `v0` alias.

## Changed

- **Operator chat findings are retained for 180 days of inactivity by default.** Earlier conversations and the authenticated Investigation history page keep findings accessible after analysis refreshes, and New conversation archives rather than deletes them. Live sessions still become read-only after their shorter inactivity timeout, while prepared-only conversations keep their short lifetime. Configure history retention with `server.chat.historyRetention` or `ANALYSIS_CHAT_HISTORY_RETENTION`. Reads and polling do not extend retention, and already deleted conversations cannot be recovered. See [analysis chat](https://github.com/willie-yao/aster/blob/v0.10.0-rc.3/docs/server.md#analysis-chat).
- **Published images and release assets carry signed build provenance attestations.** Each image is attested at its pushed digest, with the attestation stored both against the repository and beside the image in the registry. This includes the `sha-` images built from `main`. Every release payload named in `SHA256SUMS` is attested as well; the checksums file itself is not. Provenance records where an artifact was built, not that it is correct or safe. See [release verification](https://github.com/willie-yao/aster/blob/v0.10.0-rc.3/docs/releasing.md#verifying-a-release).
- Onboarding examples, reusable workflow references, and the setup skill now pin the published v0.10.0-rc.2 release. Existing consumers retain their own refs. To test this candidate, pin the deployment explicitly to v0.10.0-rc.3.

## Fixed

- **Pull request triage no longer depends on Fix configuration for presubmit coverage.** Triage could show a passing CI state while omitting a failing presubmit because catalog coverage depended on Fix settings. With TestGrid discovery, triage now includes applicable presubmits for the configured source repository regardless of dashboard annotations or AI/Fix settings.

## Breaking

- **Private chat state is upgraded automatically with a version-4 backup.** Downgrading to a version-4 server requires restoring `sessions.json.v4.bak`, which does not include conversations created after the upgrade. The backup is operator-managed and is not pruned by history retention. The Helm chart uses a `Recreate` server rollout when chat is enabled; manual deployments must stop old server replicas before starting the new version so different chat-state schemas are not written concurrently.
