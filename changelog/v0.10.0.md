v0.10.0 is the first stable release in Aster's version line. It brings evidence-first Prow and TestGrid failure analysis to GitHub Pages and Kubernetes-native deployments, with optional, guarded maintainer investigation and follow-up. This release improves source-grounded diagnoses, pull request triage, operator chat and Fix workflows, dashboard performance, and release verification.

These notes summarize the Aster version line, including the v0.9.0 candidates that never became a stable release and the three v0.10.0 candidates. A deployment already on v0.10.0-rc.3 does not need a configuration change or an AI re-analysis: the critique contract remains at version 18. Direct upgrades from older candidates should review the Breaking section before deploying.

## Highlights

- **One engine serves project-owned dashboards.** A consumer supplies its own configuration and prompt while Aster runs the shared analysis and UI. Deploy a public dashboard through GitHub Actions and Pages or run the engine and server in Kubernetes with optional authenticated operator features. See [onboarding](https://github.com/willie-yao/aster/blob/v0.10.0/docs/onboarding-a-new-project.md).
- **Failure analysis stays grounded in observed evidence.** Bounded, read-only artifact and pinned-source tools, evidence planning, and deterministic critique gate published diagnoses. Citations are checked against evidence the analyzer read; a verified citation does not by itself prove the proposed root cause. See [agentic analysis](https://github.com/willie-yao/aster/blob/v0.10.0/docs/agentic.md).
- **Pull request triage separates baseline failures, known flakes, shared failures, and unexplained checks.** The shared-failure view needs no model call; Kubernetes deployments can enable on-demand investigation. Attribution describes the observed results and does not establish that a pull request caused a failure. See [pull request triage](https://github.com/willie-yao/aster/blob/v0.10.0/docs/pull-request-triage.md).
- **Recurring causes remain visible across fetch windows.** Maintainers can resolve an individual cause without hiding other failures in its group, and a new matching failure reopens it. Retained run history expands what the dashboard can display without increasing the number of builds analyzed.
- **Authenticated maintainers can investigate and review a proposed follow-up.** Cause-scoped chat can compare a failure with later runs, treating a later pass as non-reproduction evidence rather than proof of a fix. On-demand issue creation and draft-fix publication require explicit review and confirmation. Agent Sandbox Fix generation remains experimental, disabled by default, and outside standard onboarding; it neither approves nor merges a pull request. See [Fix proposals](https://github.com/willie-yao/aster/blob/v0.10.0/docs/fix-prs.md).
- **Operators have health and notification signals.** Runtime trends, problem-ranked Analysis Health, configurable attention thresholds, and optional SMTP alerts distinguish ongoing failures, changed failure modes, and recovery. See [notifications](https://github.com/willie-yao/aster/blob/v0.10.0/docs/notifications.md).

## Changed

- **Cause investigations distinguish historical evidence from current source.** Aster reads the exact source revision tested by a failed build, verifies cited file ranges against the bytes read, and checks proposed remediation against the current immutable tip of the tested branch. A proposal without current-source evidence stays inconclusive rather than being presented as a verified fix. The Investigate cause panel leads with cross-build evidence.
- **Manual Fix requests can investigate cases that the automatic path declines.** Low-confidence, transient, or incomplete findings can be passed to the coding agent with their uncertainty shown as warnings. Automatic eligibility, patch and repository safeguards, and explicit pull request confirmation remain in place.
- **Operator chat findings persist across analysis refreshes.** Authenticated Investigation history retains conversations for 180 days of inactivity by default, independently of the shorter live-session timeout. A chat-originated Fix proposal retains its own selected finding and evidence, so expiring or deleting the conversation does not silently revoke the proposal. Cancel proposals explicitly. See [analysis chat](https://github.com/willie-yao/aster/blob/v0.10.0/docs/server.md#analysis-chat).
- **Release artifacts have verifiable provenance.** Images are attested at their published digests, including images from main, and release assets named in `SHA256SUMS` carry signed build provenance. This establishes where an artifact was built, not that its contents are correct. See [release verification](https://github.com/willie-yao/aster/blob/v0.10.0/docs/releasing.md#verifying-a-release).
- **Release tagging is validated.** The Release tag workflow checks that notes exist and are indexed, version precedence moves forward, the version is not already served by the Go module proxy, and both release tags are available. It creates the root and `backend/` tags together from the reviewed tip of main. Publishing uses these curated notes instead of a generated commit list. The stable release also establishes the moving `v0` alias after its artifacts are published.

## Fixed

- **Pull request triage includes applicable presubmits even without Fix configuration.** TestGrid discovery no longer leaves a failing presubmit out of the triage view and incorrectly shows a passing state.
- **Late action-draft responses stay with their originating draft.** Navigating between drafts while confirm, cancel, refine, or recovery is pending no longer lets the previous draft overwrite the current draft's error or redirect navigation.
- **Secondary dashboard routes load on demand.** Initial compressed JavaScript, including static modulepreloads, is approximately 28% smaller; shared navigation remains available while a route loads.
- Signed-out pull request and shared-failure views display a sign-in prompt rather than unauthorized investigation errors. Signing out clears privileged investigation state.
- Fetch progress reports measured reuse instead of zero when analyses are actually reused, and no longer double-counts an analysis cancelled before it starts.
- Multiline cause-chat questions no longer move the causal group during drafting, and desktop job headers keep the status label clear of long titles.
- The engine and Fix executor images include fixes for known Go and container dependency vulnerabilities.

## Breaking and upgrade notes

- Deployments older than v0.9.0-rc.13 also need the earlier configuration changes: provider coordinates and cache generation moved out of `project.yaml`, and removed semantic-judge and Agent Sandbox analysis-shadow settings must be dropped. Those changes were already present in rc.13, not introduced after rc.3. Review the current [project configuration](https://github.com/willie-yao/aster/blob/v0.10.0/docs/project-configuration.md) and [Kubernetes reference](https://github.com/willie-yao/aster/blob/v0.10.0/docs/kubernetes-reference.md) before a direct upgrade.
- Local builds require Go 1.26.8 or later.
- Private fetch-status schema 14 and history schema 6 replace the earlier formats without migration. Status is recreated on the next fetch pass and historical progress begins again with newly completed passes. AI analysis caches and action state are not reset by this change.
- Private chat storage is upgraded with a version-4 backup. A rollback to a version-4 server requires restoring `sessions.json.v4.bak`, which excludes conversations created after the upgrade. Manual deployments with chat enabled must stop the old server replicas before starting the new version; the Helm chart uses a `Recreate` rollout.
- The unused `chat_fix_min_confidence` capability field is removed. Saved exact-analysis Fix previews from earlier versions must be regenerated, as must exact-JUnit previews lacking a complete action-owned handoff. Confirmed receipts and unknown-write reconciliation remain recoverable.
- Onboarding plans no longer accept the unused `failure_stage`, `failure_category`, and `failure_action` fields.
- Unused Go APIs and frontend utility exports have been removed, including `promptauthor.Validate`. Update custom tooling that imported them; the diagnostic-authoring skill now describes explicit prompt-structure review and the existing byte limit.
- Recovering a missing `backend/` tag on an older published version requires `RELEASE_ALLOW_BACKWARD=true` with `RELEASE_TAGS_ONLY=true`. Publishing a patch for an older major is not supported by the release automation.
