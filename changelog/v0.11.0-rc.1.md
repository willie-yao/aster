The first release candidate for v0.11.0 makes Agent Sandbox Fix generation more reliable and easier to diagnose, improves analysis chat source investigation and recovery, makes action and Helm upgrades safer, and clarifies investigation history.

These notes cover changes since v0.10.0. The critique contract remains at version 18, so upgrading does not invalidate AI analysis caches. Prepared cause findings are regenerated once because the chat prompt changed. Review Breaking and upgrade notes before deploying. This is a pre-release and does not advance the stable `v0` alias. Existing consumers keep their own refs; to test this candidate, pin the deployment explicitly to v0.11.0-rc.1.

## Changed

- **Fix proposals can guard repository code that caused or failed to handle a failure.** For example, test code that requests an image version missing from a region can now receive a fail-fast guard instead of an automatic "no repository change". The agent still makes no change when no repository code is causally involved. The draft PR's **Proposed change** now describes the patch using the coding agent's own summary rather than the published suggested fix.
- **Failed validators produce warned previews more consistently.** Failed or timed-out validators on pattern and single-build Fix previews now produce a warned preview with a failed verification verdict, matching exact-JUnit previews. Critique concerns are also warnings. Safety and integrity checks still reject the preview. Long test names no longer make a preview fail title validation.
- **Fix generation enforces its configured model-step budget.** The executor stops runs that exceed the configured step allowance plus one wrap-up step. The elapsed timeout still applies.
- **The Fix proposal dialog is easier to read.** It shows the finding first, followed by one **Treat this finding as a hypothesis** block that lists each reason once. Generation progress remains visible in the dialog footer, and the maintainer instruction is read-only while a preview is generating.
- **Analysis chat reads source more accurately.** `read_repo_file` returns whole lines prefixed with 1-based line numbers, supports paging with `next_offset`, and marks a single line too long to fit as `partial_line`. `grep_repo` searches up to 1 MiB of each file and reports larger files under `partially_scanned_files`, so zero matches are not mistaken for absence. Long context lines are shortened with a `...<truncated>` marker.
- **Investigation history is easier to find and interpret.** Earlier conversations start collapsed and load only when opened. The navigation control shows a History label. Saved conversations show their scope, archived or read-only status, original evidence builds, comparison build, pinned source, and retention when available. Historical transcripts no longer offer Fix actions.
- **Starting a new conversation dismisses its prepared cause finding.** Archiving a conversation that holds a prepared finding dismisses that finding for every operator for `server.chat.historyRetention`. Later conversations for the cause start empty unless a newer comparison run or cause revision is prepared. The New conversation dialog now states whether the previous conversation remains in history and whether its prepared finding will be dismissed. See [analysis chat](https://github.com/willie-yao/aster/blob/v0.11.0-rc.1/docs/server.md#analysis-chat).
- **Maintainers can publish patches for maintained minor lines.** Patch releases can be cut from a reviewed `release/MAJOR.MINOR` branch after a newer minor ships. Newly indexed release-note pull requests receive read-only preflight validation. Older-line patches do not replace GitHub Latest, the moving major alias, or OCI `latest`. OCI `latest` now advances only to digests verified for the highest stable release. See [release branches](https://github.com/willie-yao/aster/blob/v0.11.0-rc.1/docs/releasing.md#release-branches-backports).

## Fixed

- **Analysis chat no longer reports an answered question as lost after a connection interruption.** Continue, Cancel, and page restore now ask the server what happened to the request, wait while it is still running, and show the answer when it exists. The open conversation clears an interrupted question's warning as soon as the server reports its outcome. Server logs now distinguish citation-validation retries, accepted answers, and failed turns.
- **GitHub Copilot Fix previews work again.** Every Copilot Agent Sandbox Fix preview previously failed with "coding agent exited with status 1". The executor now uses OpenCode's bundled Copilot provider with the matching model route for Responses and Chat Completions.
- **Failed Fix previews show the provider or OpenCode error.** A bounded, redacted diagnostic now replaces a generic runtime error, including the provider HTTP status and error code when available.
- **Fix generation has enough time to finish a Sandbox run.** Asynchronous generation and synchronous previews default to the greater of 10 minutes or the configured agent timeout plus 5 minutes.
- **Admitted exact-JUnit Fixes survive analysis text changes.** A Fix admitted from a current analysis remains available when only analysis text is regenerated before the patch is ready or confirmed. Changed JUnit evidence, cause content, or source and generation-base identity are still rejected.
- **Multi-repository Prow builds resolve the commit they tested.** Aster reads `clone-records.json` to pin each eligible repository, including previously published builds. This enables source tools and file links for those analyses. When the exact commit remains unknown, Fix explains why it is unavailable instead of reporting that the analysis changed.
- **Persistent action confirmations always produce a write-audit record.** Aster records the original request owner and creation time under a stable audit identity, preserves known result URLs, and reconciles persistence failures before reporting confirmation as complete.
- **Fix runtime edge cases are handled.** The executor shallow-fetches the pinned commit, runs Go validators with the image toolchain, and reports deletion or rename attempts as out-of-scope changes. Helm accepts omitted or empty validator lists, and no-change summaries retain the agent's final text.
- **Pull request attribution compares results from the pull request's own base branch.** Failures are no longer marked pre-existing or flaky from unrelated branch results.
- **Transient fetch failures no longer remove published state.** Aster retains the last observed runs for affected jobs and records follow-up failures without failing publication or announcing false recoveries.

## Breaking and upgrade notes

- **Deploy the dashboard server and Agent Sandbox executor from the same release.** The executor result gains an `agent_summary` field, and Copilot Fix configuration depends on the new executor provider selection. Upgrade the executor digest and dashboard image together.
- **Action request and preview responses return `warnings`.** Responses now contain a list of `{code?, message}` objects instead of a single `warning` string. The persisted action request state version changed, so action requests in flight during the upgrade are discarded and must be started again.
- **Interactive Helm deployments require one server replica.** Rendering fails when actions or pull request and shared-failure escalation are enabled with `server.replicaCount` above `1`. Reduce the count to `1` before upgrading. Interactive servers use `Recreate` rollouts. Read-only and chat-only servers may still use multiple replicas when chat storage supports advisory locking, atomic rename, and file and directory synchronization.
- **Copilot Fix configurations must declare the API and endpoint used by OpenCode.** GPT-5 and later use Responses except `gpt-5-mini`; other models use Chat Completions. Leave reasoning effort unset for GPT-6 on Copilot Responses in both `project.yaml` and `agentSandbox.fixRuntime.modelProvider.reasoningEffort`; Aster rejects an explicit value because pinned OpenCode 1.18.2 does not honor it. See [Agent Sandbox Fix configuration](https://github.com/willie-yao/aster/blob/v0.11.0-rc.1/docs/project-configuration.md#experimental-agent-sandbox-fix-configuration) and the [Agent Sandbox Fix runtime](https://github.com/willie-yao/aster/blob/v0.11.0-rc.1/docs/kubernetes-reference.md#agent-sandbox-fix-runtime).
- **Fix runs that exceed `max_turns` stop.** They no longer continue until the elapsed timeout.
- **Provider request failures use a new category.** Non-authentication provider 4xx responses other than 408 and 429 now use `provider_request` instead of `runtime_infrastructure`.
- **Explicit action timeouts must cover Fix generation.** When Fix is enabled, server startup rejects an explicit `ACTION_TIMEOUT` below the configured agent timeout plus 5 minutes. An explicit value also controls ordinary action HTTP handlers. See [Fix configuration](https://github.com/willie-yao/aster/blob/v0.11.0-rc.1/docs/fix-prs.md#required-project-configuration).
- **Some saved Fix and chat state must be recreated.** Ready exact-JUnit Fix handoffs saved with handoff version 4 require regeneration. Existing conversations on multi-repository builds need a new conversation because newly pinned metadata and file links can change the published analysis identity.
