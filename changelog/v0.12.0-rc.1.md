The first release candidate for v0.12.0 lets failures that stop before JUnit start Fix proposals, lets cause chat compare against the default branch, keeps diagnostics when Agent Sandbox Fix runs time out, and makes first-time onboarding pin released engine versions.

These notes cover changes since v0.11.0. The critique contract remains at version 18, so upgrading does not invalidate AI analysis caches. Review Breaking and upgrade notes before deploying. This is a pre-release and does not advance the stable `v0` alias. Existing consumers keep their own refs; to test this candidate, pin the deployment explicitly to v0.12.0-rc.1.

## Changed

- **Build-level failures can start Fix proposals.** Causes and analysis chats for failures that stopped before JUnit results previously offered no Fix proposal. A completed chat finding on a build-level failure can now start one, and cause cards link to the representative build failure page. Existing source, failure-evidence, and confirmation checks still apply.
- **Cause chat can compare against the default branch.** When a build tested another branch, cause-scoped chat can read the default branch's immutable tip as comparison-only source `default` to check whether the cause logic differs there. Remediation still requires evidence from the tested branch, and Fix targets are unchanged.
- **Onboarding pins the released engine by default.** Released CLIs scaffold Pages workflows against their own release instead of a moving engine ref. Doctor warns about unfinished prompt comments and unrecognized engine refs. First-time setup includes a manual prompt starter, so coding-agent skills are optional.
- **Investigation History moved into the operator navigation.** It appears alongside Health and Usage in the desktop sidebar. On mobile it remains an icon-only shortcut in the top bar.

## Fixed

- **Agent Sandbox Fix timeouts keep their diagnostics.** A timed-out run previously could be killed by its Pod deadline during normal image pull and VM startup before the executor reported anything, leaving only `timed_out`. Pod deadlines now include a fixed startup allowance, and timed-out results retain a bounded, redacted executor summary and any partial validation results. Cleanup confirmation allows 90 seconds for slow VM termination and no longer masks the timeout.

## Breaking and upgrade notes

- **Deploy the Helm chart and dashboard image from the same release.** The Agent Sandbox admission policy now pins the Pod deadline to the configured timeout plus a 2-minute startup allowance and 15-second result grace, which is 735 seconds for a 10-minute timeout. Mixing this chart with an older server, or an older chart with this server, rejects every new Fix Sandbox. Configured executor timeouts and the 30-minute maximum are unchanged.
- **Development Pages builds must pass `-engine-ref`.** Onboarding no longer defaults to a moving engine ref, so builds from an unreleased CLI must name the engine ref explicitly.
