The second release candidate for v0.12.0 lets exact-analysis Fix proposals target the repository's default branch, makes generated Fix patches more likely to resolve the failure, raises the default Agent Sandbox memory limit, and links job pages to their Prow definitions.

These notes cover changes since v0.12.0-rc.1. The critique contract remains at version 18, so upgrading does not invalidate AI analysis caches. Review Breaking and upgrade notes before deploying. This is a pre-release and does not advance the stable `v0` alias. Existing consumers keep their own refs; to test this candidate, pin the deployment explicitly to v0.12.0-rc.2.

## Changed

- **Exact-analysis Fix proposals can target the default branch.** When a job tests an older branch, for example `release-1.24`, and the repository's default branch is `main`, the Fix dialog offers both. The tested branch remains the default. With the default-branch target, Aster pins the default branch's current head, tells the coding agent where the failure was observed and to make no change if the causal logic is absent there, and opens the draft PR against the default branch. The PR names both branches and suggests commenting `/cherry-pick <tested branch>` after merge. The failure-commit ancestry check applies only to the tested-branch target; all other source, base, evidence, and safety checks are unchanged. See [Fix PRs](../docs/fix-prs.md#exact-failure-analysis-handoff).
- **Fix proposals prefer changes that resolve the failure.** Fix prompts now look for a change that makes the failed operation succeed first, and may rely on documented external facts stated as assumptions to validate. A patch that only fails earlier must start its summary with `Guard only:` and say what remains unfixed.
- **Every Fix preview gets one critique when dashboard AI is configured.** Agent Sandbox previews previously skipped critique because `critique_retries` is 0. Each preview now receives one warning-only critique without another Sandbox run. `critique_retries` controls only regeneration.
- **Job pages link to their Prow definitions.** TestGrid job pages link to the job's definition in kubernetes/test-infra and show the configured checkout branch when known, so maintainers can find jobs that still test an older release branch. Links use the discovery revision when recorded. The dashboard does not edit job definitions.
- **The default Agent Sandbox Fix memory limit is now 1Gi.** It was 512Mi. Deployments that rely on the default allow more memory per Fix Sandbox. Explicit memory-limit overrides and the 128Mi memory request are unchanged.

## Fixed

- **Fix pull requests keep existing file modes.** Generated Fix commits previously reset every changed file to `100644`, stripping executable bits from scripts. Existing files now keep their modes, and new files use `100644`.

## Breaking and upgrade notes

- **Regenerate saved exact-analysis Fix requests.** The Fix handoff version changed, so exact-analysis Fix requests saved by an earlier version must be started again after upgrading.
- **Agent Sandbox Fix previews make one more model call.** The warning-only critique uses the dashboard AI endpoint once per preview when one is configured.
