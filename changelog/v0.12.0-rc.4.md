The fourth release candidate for v0.12.0 improves failure attribution, analysis and chat evidence, Fix review and recovery, and dashboard freshness reporting. It also adds renewable GitHub App authentication for reads and restricts publication to recognized public data files.

These notes cover changes since v0.12.0-rc.3. Review the breaking and upgrade notes before deploying. This is a pre-release and does not advance the stable `v0` alias. To test it, pin the deployment explicitly to v0.12.0-rc.4.

## Breaking and upgrade notes

- **GitHub App credentials now select App authentication for reads.** Configuring either `ASTER_APP_ID` or `ASTER_APP_PRIVATE_KEY` selects App mode, even when PR commenting is disabled; an incomplete pair is an error. App authentication takes precedence over static tokens, including the Pages workflow's `GITHUB_TOKEN`, and failures do not fall back to another credential. Before upgrading an existing comment-only installation, install the App on every read repository, including `kubernetes/test-infra` for TestGrid discovery and each configured source repository. Grant Contents read and Pull requests read where triage or escalation is enabled, with any required organization approval. Installing only on the consumer or comment repository is insufficient. See [GitHub read authentication](https://github.com/willie-yao/aster/blob/v0.12.0-rc.4/docs/github-read-auth.md).
- **The public JSON contract changed.** `pass_rate_recent` is nullable in job summaries and details, and summary `overall_status` can be `UNKNOWN` when no completed outcomes are available. Flakiness output no longer contains `duration_history`; the Go `TestFlakiness.DurationHistory` field and `DurationPoint` type are removed. Per-run durations, duration summaries, runtime trends, and flakiness classification remain available.
- **Fix runtime timeout validation is stricter.** `ai.fix_prs.agent_runtime.timeout` accepts positive whole seconds or minutes up to 30m, such as `90s` or `10m`. Compound or fractional durations, leading zeros, and surrounding whitespace are rejected. Empty or null values retain the 10m default. Helm and runtime deadlines now agree for values such as `90s`.
- **Inline fetcher credentials are rejected.** Doctor and GitOps rendering now reject credential-named inline values in `fetcher.extraEnv`, matching server validation. Move those credentials to Kubernetes Secret references. Non-secret inline settings remain supported.
- **Existing analysis caches are revalidated under critique contract version 19.** Upgrades can trigger new analysis when cached results fail the current acceptance gate. Cache-key construction is unchanged. JUnit `<error>` cases also now count as failures, so previously omitted tests may receive new analyses.

## Changed

- **GitHub App read tokens renew automatically.** Long-running server and worker processes obtain repository-scoped read tokens in memory without replacement read PATs or restarts for token expiry. App-mode discovery downloads YAML through the authenticated Contents API; static-token and anonymous discovery retain the unauthenticated raw-content CDN. Rotating the App private key still requires updating its Secret and restarting processes that load it from environment variables.
- **Failure pages lead with the active cause and next step.** The overview separates recent reliability from the latest run, explains pattern counts and unanalyzed failures, and filters jobs from the failed-latest-run count. Needs attention cards are more compact, omit test alerts already covered by active patterns, and include shared PR failures when triage is enabled. Affected builds appear as a dated ledger; phone layouts and status filters are clearer.
- **Shared PR failures can reuse published base-branch analysis.** Pages show grouping evidence, affected PRs, and the source run alongside its analysis, chat, and Fix path. Matching job and test names are described as observed similarities rather than proof of a shared cause or that a PR is uninvolved. Historical revisions and incomplete observations are explicitly qualified.
- **Fix preparation and review use full-size workspaces.** Branch selection and instructions remain beside the finding, and review emphasizes the diff, rendered PR description, file navigation, and checks. Persistent action bars, mobile layouts, and keyboard shortcuts keep revision and confirmation accessible. `make dev-mock` now supports the chat Fix flow without credentials.
- **Interactive chat can investigate for more rounds.** Test, cause, and pattern chat use the effective `ai.max_iters`, capped at 100, with tool-call caps scaled accordingly. This can increase per-turn model usage. Engine-prepared findings retain their eight-round cap. Baseline comparisons are offered before the first question when a qualifying passing run exists, pair evidence reads, and consult boot or console logs for nodes that never registered.

## Fixed

- **Analysis preserves usable drafts and evidence at budget limits.** Investigations reserve time to finalize and retain stronger drafts when later responses are weaker. Tool JSON stays within its 32 KiB limit while retaining fitting excerpts and navigation prefixes. Citations use accepted visible evidence and survive unrelated ledger overflows; excerpts from long lines retain the cited passage within the 2000-byte limit. Compaction preserves caller transcripts and tool-call pairing, and saved chat turns record why investigation stopped.
- **Cache retries and pattern results follow current validity rules.** Safe, grounded analyses rejected by investigation floors count against the existing three-attempt budget and can reuse valid published output once it is spent. Expired, invalid, or stale analyses still refresh. Severity casing and surrounding whitespace no longer reject recognized values. Mismatched pattern-cache versions regenerate, and valid hits retain their original generation time.
- **Timed-out fetch passes retain completed private analysis work.** Checkpoints and traces let later passes reuse accepted results. These passes still leave the published dashboard unchanged and skip pattern analysis and follow-ups. Explicit cancellation still rolls back uncommitted state.
- **Publication protects supporting data and private files.** Dashboard publication waits for required supporting writes, and stale jobs are pruned only after successful publication. Files are replaced independently, so mixed generations remain possible. The server and Pages staging allow only recognized public files, reject symlinks, and remove leftover private files from staged output while preserving public provenance.
- **Partial refreshes and test outcomes are reported accurately.** Refresh warnings identify failed or missing jobs and carried-forward observations without advancing their last successful fetch times. Recovery clears the warning, and cancelled PR triage preserves its previous output. JUnit `<error>` details are retained, skipped duplicates do not hide executed results, and completion-metadata read errors other than missing files use the existing skip or unavailable handling.
- **PR attribution uses usable completed evidence.** A pending retest of the same revision retains the last completed failure; a newly pushed revision remains running. Base attribution uses each job's newest completed run with usable test outcomes, without combining runs. Unread applicable checks prevent an otherwise passing verdict, and older-revision results do not contribute to current widespread attribution. Reliability counts completed outcomes within the newest 10 published runs.
- **Recovery and detail views distinguish uncertainty from current evidence.** Retained patterns compare same-cause recurrence identities rather than resetting for unrelated analyzed failures; incomplete evidence remains conservative. Resolution reads preserve resolved state while loading and offer retry on errors. Low-pass-rate attention entries survive normalization, direct build-failure links handle empty results, expired run links select an available run, and PR pages expose snapshot age and unread checks. Evidence views no longer fabricate controller-log paths or expect fields the backend never emitted; published artifact/source links and AI citations remain available.
- **Fix retries preserve reviewed work without duplicating writes.** Safe target-branch advances are accepted when they preserve the pinned base and leave patched files unchanged, without rebasing. Failed, cancelled, or expired requests can restart with revised branch or instructions. Definitive pre-write failures keep previews retryable; GitHub create responses of HTTP 500 or higher, lost responses, and missing result URLs remain unknown outcomes requiring reconciliation.
- **Durable write guards and unfinished cleanup survive failures.** Unreadable or invalid saved write state requires repair instead of being replaced with empty state, while dashboard reads and ordinary chat remain available. Unfinished Fix cleanup survives shutdown without blocking File Issue admission. Safe diff context is accepted, and a confirmed closed-unmerged pattern PR permits another Fix.
- **Escalation and API errors retain their quality and retry guidance.** Preliminary PR and shared-failure analyses retain warnings and allow up to three preliminary results per subject and evidence build. Escalations honor output-token limits and usage accounting; action AI requests retain their service tier. Chat errors preserve safe messages, action conflicts return HTTP 409, and admission limits return HTTP 429. Compact private chat state postpones file-limit exhaustion without adding eviction; truncation includes its elision marker within byte limits.
- **Deployment wiring and feature discovery recover correctly.** Discovery and chat-only Helm deployments receive the configured GitHub read token. Invalid local Fix runtime configuration disables Fix while preserving issues, chat, and reads; Helm rejects Fix enabled without its runtime deployment. Kubernetes doctor checks the selected values file, and both doctors reject invalid static origin restrictions. Capability discovery retries transient failures and offers manual retry. Pages base paths correctly decode `branding.base_path`, and empty-dashboard guidance names `discovery.testgrid_dashboard`; deployment guidance clarifies that fetch timeouts include analysis and Pages runners need Python 3.
