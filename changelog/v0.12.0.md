Aster v0.12.0 improves evidence-grounded investigations, guarded Fix proposals, pull request attribution, and dashboard freshness reporting. It adds renewable GitHub App authentication for reads, passing-baseline comparisons, default-branch Fix targeting, and a diff-first review workspace.

These notes cover changes since v0.11.0, including all five release candidates. The implementation is unchanged from v0.12.0-rc.5. Review the breaking and upgrade notes before deploying. This stable release advances the `v0` alias; consumers pinned to an exact tag or commit keep their selected version.

## Breaking and upgrade notes

- **Upgrade the Helm charts, dashboard image, and Fix executor together.** The Fix admission policy now pins Pod deadlines to the execution timeout plus a 2-minute startup allowance and 15-second result grace: 735 seconds for a 10-minute timeout. Mixing old and new admission/runtime contracts rejects Fix Sandboxes. Resolve the matching executor image digest for deployment. The default Fix memory limit rises from 512Mi to 1Gi; explicit overrides and the 128Mi request are unchanged.
- **Saved exact-analysis Fix requests use a new handoff contract.** Requests saved under an older contract must be started again after upgrading.
- **GitHub App credentials now select App authentication for reads.** Either nonempty `ASTER_APP_ID` or `ASTER_APP_PRIVATE_KEY` selects App mode, even when PR commenting is disabled; an incomplete pair is an error. App authentication takes precedence over static tokens, including Pages `GITHUB_TOKEN`, and failures do not fall back. Existing comment-only installations must add every read repository, including `kubernetes/test-infra` for TestGrid discovery and each configured source repository. Grant Contents read and Pull requests read where triage or escalation is enabled, with any required organization approval. Consumer-only installation is insufficient. See [GitHub read authentication](https://github.com/willie-yao/aster/blob/v0.12.0/docs/github-read-auth.md).
- **The public JSON and Go contracts changed.** `pass_rate_recent` is nullable in job summaries and details; summary `overall_status` can be `UNKNOWN` without completed outcomes. Flakiness output drops `duration_history`, and Go drops `TestFlakiness.DurationHistory` and `DurationPoint`. Per-run durations, summaries, run history, runtime trends, and flakiness classification remain available.
- **Fix timeout validation is stricter.** `ai.fix_prs.agent_runtime.timeout` accepts positive whole seconds or minutes through 30m, such as `90s` or `10m`. Compound/fractional durations, leading zeros, and surrounding whitespace are rejected. Empty or null values retain the 10m default. Helm and runtime deadlines now agree for values such as `90s`.
- **Use Secret references for fetcher credentials.** Doctor and GitOps rendering now reject credential-named inline values in `fetcher.extraEnv`, matching server validation. Non-secret inline settings remain supported.
- **Cache revalidation and model usage can increase.** Critique contract 19 revalidates existing analyses without changing cache-key construction. JUnit `<error>` cases now count as failures and can receive new analyses. Interactive test, cause, and pattern chat use effective `ai.max_iters`, capped at 100, with scaled tool-call caps; prepared findings retain eight rounds. When dashboard AI is configured, every Sandbox Fix preview receives one additional warning-only critique even with `critique_retries: 0`, without another Sandbox run.
- **Development Pages builds need an explicit engine ref.** Unreleased CLI builds must supply `-engine-ref`. Released CLIs default onboarding to their own release. Pages runners require Python 3.

## Changed

- **GitHub App read tokens renew automatically.** Long-running server and worker processes obtain repository-scoped read tokens in memory without replacement read PATs or restarts for token expiry. App-mode discovery downloads YAML through the authenticated Contents API; static-token and anonymous discovery retain the unauthenticated raw-content CDN. Private-key rotation still requires updating the Secret and restarting processes that load it from environment variables.
- **Chat can compare failures with passing and default-branch evidence.** New cause conversations bind the newest fully passing retained run before the first failing member when artifact locations exist, even if dashboard JUnit is truncated. They offer "What changed since the last passing run?" before the first question. Chat compares inputs, commits, rendered resources, and node OS/kernel before logs, pairing evidence reads and using boot/console logs for nodes that never registered. It can also read the default branch's immutable tip as comparison-only source. These comparisons do not change cause membership, recovery, or Fix targets; remediation still needs evidence from the tested branch.
- **More failures can start a guarded Fix investigation.** Completed chat findings for failures before JUnit can start Fix proposals. Exact-analysis proposals can target the repository's default branch when it differs from the tested branch; the tested branch remains the default. The alternative pins the default-branch head, identifies where the failure occurred, and asks the coding agent to make no change if the causal logic is absent. Only the tested-branch target requires failure-commit ancestry. Drafts name both branches and suggest `/cherry-pick <tested branch>` when applicable. See [Fix PRs](https://github.com/willie-yao/aster/blob/v0.12.0/docs/fix-prs.md#exact-failure-analysis-handoff).
- **Fix preparation and review use full-size workspaces.** Findings sit beside branch selection and instructions. Review leads with a line-numbered diff, rendered PR description, file navigation, and checks, with persistent revision/confirmation controls and phone layouts. Draft PRs retain Prow failure links, AI-generation disclosure, verification, and backport guidance outside template-filled prose. `make dev-mock` supports the chat Fix flow without credentials. Proposals prioritize resolving changes; guard-only summaries identify what remains unfixed, and documented external facts remain assumptions to validate.
- **Overview and detail pages separate reliability, latest status, and evidence.** Needs attention cards explain cause counts and unanalyzed failures, omit test alerts covered by active patterns, and include shared PR failures when triage is enabled. Detail pages lead with the active cause and next step; affected builds form a dated ledger. Job pages link to pinned Prow definitions and show checkout branches. Mobile layouts, filters, and sticky side rails are clearer, and Investigation History sits with operator navigation.
- **Shared PR failures can reuse published base-branch analysis.** Pages show grouping evidence, affected PRs, and the source run alongside its analysis, chat, and Fix path. Matching names indicate observed similarities rather than a verified common cause or proof that a PR is uninvolved. Historical revisions and incomplete observations are qualified explicitly.
- **First-time onboarding is easier to finish.** Doctor warns about unfinished prompt comments and unrecognized engine refs. A manual prompt starter makes coding-agent skills optional, while released CLI defaults keep generated Pages workflows on an exact engine release.

## Fixed

- **Analysis retains usable drafts and evidence at budget limits.** Investigations reserve time to finalize and preserve stronger drafts when later responses are weaker. Tool JSON stays within 32 KiB while retaining fitting excerpts and navigation prefixes. Citations use accepted visible evidence and survive unrelated ledger overflows; long-line excerpts retain cited passages within 2000 bytes. Compaction preserves caller transcripts and tool-call pairing, and saved chat turns record why investigation stopped.
- **Cache retries and pattern results follow current validity rules.** Safe grounded results rejected by investigation floors count against the existing three-attempt budget and can reuse valid published output once spent. Expired, invalid, or stale analyses still refresh. Severity casing/whitespace no longer rejects recognized values. Unsupported pattern-cache wrappers regenerate, and valid hits keep their generation time.
- **Deadline-limited fetches retain completed private analysis work.** Checkpoints and traces let later passes reuse accepted results. These passes still leave the published dashboard unchanged and skip pattern analysis and follow-ups. Explicit cancellation rolls back uncommitted state.
- **Publication protects supporting data and private files.** Dashboard replacement waits for required supporting writes; stale jobs are pruned only after successful publication. Files remain independently replaced, so mixed generations are possible. The server and Pages staging allow only recognized public files, reject symlinks, and remove leftover private files from staged output while preserving public provenance.
- **Partial refreshes and test outcomes are reported honestly.** Warnings identify failed/missing jobs and carried-forward observations without advancing their last successful fetch times. Recovery clears the warning; cancelled PR triage preserves prior output. JUnit `<error>` details are retained, skipped duplicates do not hide executed results, and unreadable completion metadata uses skip/unavailable handling rather than pretending the build is pending.
- **Attribution uses usable completed evidence.** Same-revision pending retests retain the last completed failure; new revisions remain running. Base attribution uses each job's newest completed run with usable test outcomes, without combining runs. Unread applicable checks prevent an otherwise passing verdict, and old revisions do not contribute to current widespread attribution. Reliability counts completed outcomes within the newest 10 published runs.
- **Recovery and detail views preserve uncertainty.** Retained patterns compare same-cause identities rather than resetting for unrelated analyzed failures; incomplete evidence stays conservative. Resolution reads preserve resolved state while loading and offer retry on errors. Low-pass-rate attention entries survive normalization, direct build-failure links handle empty results, expired run links select an available run, and PR pages expose snapshot age/unread checks. Evidence views no longer fabricate controller-log paths or expect fields the backend never emitted; real artifact/source links and citations remain.
- **Fix retries preserve reviewed work and write safety.** Unrelated branch advances are accepted when the pinned base stays reachable and patched files are unchanged, without rebasing. Failed, cancelled, or expired requests can restart with revised targets/instructions. Definitive pre-write failures keep previews retryable; HTTP 500+ create responses, lost responses, missing URLs, and failed audit/reconciliation remain protected as unknown outcomes. Sanitized failures identify the GitHub operation/repository; fork-mode guidance explains classic PAT `workflow` scope when needed.
- **Fix state, timeout diagnostics, and file modes survive failures.** Invalid/unreadable durable write state requires repair instead of replacement with empty state, while reads and ordinary chat remain available. Unfinished cleanup survives shutdown without blocking File Issue admission; cleanup confirmation allows 90 seconds. Timeouts retain bounded redacted executor diagnostics and partial results. Safe diff context is accepted, a confirmed closed-unmerged pattern PR permits another Fix, existing file modes are preserved, and new files use `100644`.
- **Escalation and API errors retain their quality state.** Preliminary PR/shared-failure analyses keep warnings and allow up to three explicit preliminary results per subject/evidence build. Escalations honor output-token limits and usage accounting; action AI requests retain their service tier. Chat errors preserve safe messages, action conflicts return HTTP 409, and admission limits return HTTP 429. Compact private chat state postpones file-limit exhaustion without eviction; truncation includes its elision marker within byte limits.
- **Deployment wiring and capability discovery agree.** Discovery and chat-only Helm deployments receive the configured GitHub read token. Invalid local Fix runtime configuration disables only Fix; Helm rejects Fix enabled without its runtime deployment. Kubernetes doctor checks the selected values file, and both doctors reject invalid static origin restrictions. Capability discovery retries transient failures and offers Retry. Pages correctly decodes `branding.base_path`, empty-dashboard guidance names `discovery.testgrid_dashboard`, and fetch-timeout guidance includes analysis.
- **Search keeps keyboard focus and readable text.** Fullscreen search starts in the input, contains Tab navigation, and restores the invoking control on dismissal. Its placeholder meets normal-text contrast in both themes.

## Known limitation

Generated Fix PR text can disagree with Checks about which validations ran. Treat the structured Checks and explicit unrun-test caveats as authoritative, and correct contradictory draft text before confirming it. Fix generation remains experimental and requires maintainer review; a preview is not proof that its patch resolves the failure.
