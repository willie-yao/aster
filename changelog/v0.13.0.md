Aster v0.13.0 adds guided fix investigations and carries the operator’s requested outcome into Fix generation. These notes cover changes since v0.12.0. The stable `v0` alias advances to this release; exact tag and commit pins keep their selected version.

## Breaking and upgrade notes

- **Remove `ai.fix_prs.critique_retries` from consumer `project.yaml`.** Automatic model patch review has been removed. Fix preview and action-request responses no longer include its review metadata. Configured command checks, source and patch integrity checks, maintainer confirmation, and diagnosis critique remain.
- **Regenerate older exact-analysis Fix previews.** The handoff now binds the selected human request. Requests with unknown write outcomes still require reconciliation before another write can be attempted. See [Fix proposals](https://github.com/willie-yao/aster/blob/v0.13.0/docs/fix-prs.md).

## Changed

- **Guided investigation is the default starting point.** New test, build-failure, and cause conversations can start with an optional desired outcome. Custom questions remain available, drafts survive mode switches, and existing operator conversations open for follow-up.
- **Scheduled preparation investigates a fix direction.** It checks recurrence and recovery, identifies evidence or policy gaps, and labels inferred outcomes as provisional. Prepared-only conversations keep Guided investigation selected and show an explicit ready state. Maintainers can use the finding in a Fix proposal, investigate a different outcome, or ask a custom question. Opening the result does not start another investigation or attribute preparation to the opener. Existing conversations retain their original prepared answers. See [analysis chat](https://github.com/willie-yao/aster/blob/v0.13.0/docs/server.md).
- **Fix generation retains the selected operator request.** Its guidance distinguishes resolving the cause, mitigating its impact, and improving diagnostics. It asks whether the original trigger would still fail and how to test the intended outcome. Configured checks are labeled separately from outcome assurance.
- **Image builds use Git 2.54.1.** Remote-fixer and executor images use the available Alpine patch package after the previous pin became unavailable.

## Known limitations

Prepared investigations use historical source evidence and cannot establish current-branch applicability. Inferred outcomes do not authorize changes to test purpose, coverage, assertions, or version policy. Fix generation remains experimental and requires maintainer review; passing configured checks does not prove that a patch achieves the requested outcome.
