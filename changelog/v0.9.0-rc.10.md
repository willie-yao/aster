Analysis chat becomes the way maintainers interrogate a diagnosis, and this release makes it worth opening. Cause investigations are prepared during the normal analysis run rather than starting empty, conversations are shared across operators instead of being owner-bound, recurring failures resolve one cause at a time, and a long series of gates that quietly refused good evidence were corrected. The dashboard also gets an accessibility and responsive baseline it did not previously meet.

**Upgrading forces re-analysis.** The critique contract moves from 10 to 11, so analyses cached by rc.9 are revalidated and re-run as they are encountered in the fetched build window. No `ai.cache_generation` change is needed. Expect one pass of elevated model usage after upgrading.

**Upgrading requires values changes.** `agentSandbox.causalCritic`, `analysisRuntime`, and `server.remediationInvestigation` are removed and must be deleted from consumer values before installing or rendering the chart. `source.include_presubmits` and `testgrid.dashboard` have moved in `project.yaml`. Chat-enabled deployments now roll the server with `Recreate`; a manual deployment must stop old server replicas before starting the new version. See the Breaking section.

## Added

- **Cause findings are prepared during the analysis run.** Opening a cause investigation previously started an empty conversation, so the first question spent a chat turn re-reading evidence the analysis pass had already gathered. Aster now prepares evidence-backed findings for active Fix-eligible causal groups during normal server-mode analysis runs, so opening a cause can immediately show a validated finding and offer it for a Fix proposal without consuming a turn. Preparation is best-effort and never blocks publication.
- **Analysis chat investigations are shared across operators.** A conversation was previously bound to the operator who started it, so a second maintainer looking at the same failure saw nothing. Operators now see the same attributed transcript and live turn progress for each exact test, pattern, or cause analysis. The active-turn lease still prevents concurrent interaction, and only the initiating operator can cancel a turn. Verified shared findings can be reused for owner-bound Fix proposals, and their evidence is retained through the confirmation window. Existing owner-bound chat state is migrated and canonicalized during upgrade.
- **Recurring failures resolve one cause at a time.** A recurring pattern could only be acknowledged as a whole, so a maintainer who had handled one of its causes lost sight of every other cause in the same pattern. Each causal group now carries its own Resolve failure control, and the pattern-level control appears only where per-cause resolution does not cover every cause. A cause resolution is recorded against the cause's durable signature rather than its display identity, so it survives builds joining the group or ageing out of the window, and it re-opens automatically when a newer build fails the same way.
- **Cause chat can start a Fix proposal.** A cause-scoped finding now generates a Fix using the cause's representative failed JUnit test as the exact generation target. Aster no longer displays the broader pattern chat when causal groups exist, keeping investigation and Fix authority scoped to one root cause.
- **Analyses show the evidence behind them.** The engine has always collected artifact citations while investigating a failure, verifying that each quoted passage really appears at the lines it claims, but the dashboard never displayed them, so every diagnosis had to be taken on trust. Each analysis now carries an Evidence section listing the artifacts it drew on, with the exact lines and quoted text, and the artifact path links into the build's artifact browser. Analyses cached before this release have no citations to show and gain the section as they are analyzed again.
- **Run history outlives the fetch window.** Each pass previously discarded every build older than the newest `buildsPerJob`, so run history could never grow past one window no matter how long a dashboard had been deployed. The strip now retains aged-out builds, up to 40 per job, and becomes scrollable. Retained builds are display-only and carry no test results, so analysis, flakiness classification, correlation, and AI cost still read exactly the configured depth. Retention applies to builds fetched from this version onward.
- **A navigation rail replaces the top header.** Primary navigation moves to a labelled icon rail at desktop widths and a bottom tab bar on phones, removing roughly 111px of chrome from every page. Analysis Health and AI Usage now appear only when signed in as an operator, rather than offering anonymous visitors two destinations that render a sign-in wall.
- **`aster notify-test`** sends a single test email through the relay in `project.yaml`, using the same sender the fetcher uses, so deliverability can be confirmed without waiting for an alert.

## Fixed

- **A single invalid citation no longer discards an entire answer.** Analysis chat rejected the whole artifact-grounded answer when one citation failed verification, and a citation whose line numbers did not resolve was treated the same as fabricated evidence. Aster now retains independently verified citations, falls back to quote attribution when a line range does not resolve, marks the answer partially verified when other evidence is omitted, and permits Fix investigation to use only the retained evidence.
- **A usable preliminary diagnosis is no longer discarded downstream.** Preliminary analyses were excluded from causal correlation entirely, so a failure whose root cause was sound but whose remediation or evidence coverage was unresolved never appeared in recurrence detection or causal grouping. Those diagnoses now take part in correlation, and analysis chat can turn one into a fix. Causal-group patterns remain analysis-only. An analysis whose causal claim the semantic review left contested stays ineligible for both.
- **An unstamped analysis is no longer treated as grounded.** An analysis that had never been stamped with a publication disposition passed the grounded check by default, which let unverified results reach pattern correlation and authorize write actions. Those analyses are now treated as ungrounded and reanalyzed. A failure whose only suggested remediation was to rerun the test previously discarded the entire analysis and now publishes as preliminary with a remediation warning, keeping the evidence-backed root cause and citations.
- **Preliminary analyses are no longer re-run on every pass.** They were discarded and re-analyzed with no limit, guarded only by a five minute cache window shorter than the default watch interval. Because Prow artifacts never change once a build finishes, each retry re-read identical evidence. On a dashboard with two dozen failing tests this consumed roughly 46 minutes of model time per pass. A preliminary analysis is now retried at most three times per build and failure, and reaching a grounded result clears the budget.
- **Real remediations are no longer replaced with boilerplate.** Two publication rules discarded the model's entire suggested fix when it named a source file the model had not opened or a CLI flag absent from the evidence. Both fired on exactly the fixes that were most useful, since a remediation names the file that has to change and the flag that is missing. On one deployment this replaced two of every three causal-group remediations. Flag grounding now applies to the root cause and summary only, and an unverified path is replaced in place rather than discarding the instruction around it.
- **A timed-out pass no longer deletes published job data.** A pass that ran out of time still wrote its output, and publication removes any job file it does not write, so a single slow pass could force a full re-fetch and silently drop pattern history. A timed-out pass now fails without publishing.
- **Pattern email is sent for analysis-only causal-group patterns.** Recurring pattern email was gated on a pattern supporting maintainer actions, but every systemic pattern the pipeline produces is classified into causal groups, which are analysis-only. That gate was never satisfied, so pattern alerts were never sent. On a dashboard with no persistent failures this meant no email at all.
- **A cause conversation no longer goes stale a few minutes after it opens.** Each pattern was republished with a fresh generation timestamp on every pass, including passes that reused a cached verdict, so a cause-scoped conversation recorded a timestamp the next pass invalidated and every fix proposal from it was rejected with "analysis changed". A pattern's timestamp is now the time its verdict was produced.
- **Causes and patterns are gated on evidence, not correlation freshness.** A correlation that did not refresh disabled investigation, fixes, issues, and dismissals across every affected job, even though the pattern was still the published one and its builds were fully analyzed. Eligibility now follows whether the evidence behind a cause can still be read. The `retained_stale` eligibility reason no longer exists; a pattern blocked for unreadable evidence reports `evidence_unavailable`.
- **Remediation investigations start on projects with large artifacts.** Artifact evidence was rejected on the total size of the file a citation pointed into rather than the cited region, so a citation into a typical 700 KB junit XML was discarded before the investigation began. Quotes were also compared against raw bytes, so a citation into a colorized Ginkgo log was rejected whenever ANSI codes had been stripped. Evidence is now bounded by its cited line range and compared through the shared citation rule.
- **Failed investigations say what went wrong.** A failed investigation reported the same sentence regardless of cause, so an unreachable model provider, an unreadable source revision, and a genuine lack of verifiable evidence were indistinguishable. Each now reports its own outcome, and the specific account leads rather than sitting inside a collapsed disclosure. A cause whose builds have left the window now reports "Evidence expired" rather than claiming it is stale and suggesting a refresh that cannot help.
- **`grep_artifact` distinguishes a capped match list from an incomplete scan.** A single `truncated` flag was set both when matches hit their listing cap and when the scan stopped early, which mean opposite things. Because the scan budget shrinks over an analysis, a later grep could cover very little and look identical to an early full scan, letting an analysis conclude a pattern was absent from a log it had mostly never read. Results now report `bytes_scanned` alongside `file_size`, separate `matches_truncated` and `scan_truncated` flags, and a `scan_hint` on an incomplete scan.
- **`grep_artifact` and `grep_repo` return their documented context.** An omitted `context_lines` decoded to zero, so production grep calls returned only the matching line and often lacked the context needed to connect symptom to cause.
- **Analysis chat turns no longer default to two minutes**, which could terminate a cause-scoped conversation while it was still reading evidence from several builds. The default is now ten minutes, configurable up to 30.

## Changed

- Project configuration defaults an omitted storage provider to GCS, an omitted branding title to `<name> Prow Dashboard`, and omitted Agent Sandbox Fix command policy and output bounds to the existing safe staged-diff check and runtime limits. Consumers can remove those values; explicit settings work unchanged.
- A resolved cause folds down to its header on the analysis briefing and expands again on click. Each cause's two actions share a single bar at the bottom of its card rather than being separated by the cause chat.
- The maintainer vocabulary changed with per-cause resolution: Dismiss pattern and Restore pattern are now Resolve pattern and Reopen pattern, the per-cause controls are Resolve failure and Reopen failure, and the overview's "dismissed patterns" section is now "resolved failures".
- Refresh pipeline diagnostics moved out of the Data refresh popover, which could push content past the bottom of the viewport, into a "Refresh pipeline" section on Analysis Health.
- Non-interactive, programmatic, saved-plan, and pull-request Kubernetes onboarding now requires exactly one reviewed ReadWriteMany StorageClass or existing PVC, passed as `-k8s-storage-class` or `-k8s-existing-claim`. Reviewed onboarding plan artifacts advance to schema 3 and older saved plans must be regenerated.

## Accessibility

- Reduced-motion support no longer freezes progress feedback. The global rule capped every animation at a single iteration, which ends an infinite animation rather than slowing it, so all 24 progress spinners froze mid-rotation and the chat thinking indicator stopped, making the console appear hung for precisely the people the setting accommodates. Looping motion is now decided per element.
- Keyboard users reach the job ledger without paging through roughly 300 run links. The run-history strip is a single composite tab stop with arrow key navigation, taking the Overview page from 361 tab stops to 80.
- Sending a question in analysis chat no longer moves focus to the top of the page. The composer was disabled outright while a request was in flight, and disabling a focused element hands focus back to the document; it now stays focusable while locked.
- Narrow and mid-width windows no longer break the ledger, text inputs render at 16px so iOS Safari stops force-zooming, tap targets reach 44px, functional text sits at or above 11px, and accent labels on tinted backgrounds meet the 4.5:1 contrast minimum.
- One known gap: in dark mode the "Failed" status chip measures 4.33:1 against a raised row. The red is already the lightest value in the dark ramp, so closing this requires changing the chip fill and is left for a separate change.

## Breaking

- **Causal remediation investigation is removed**, along with the experimental causal Fix preview APIs, capability fields, public JSON state, and `server.remediationInvestigation` Helm values. Each causal group now offers an authenticated analysis chat over exactly its own member builds, while Fix generation continues from the representative exact JUnit failure.
- **Analysis correction overlays are removed**, along with their API, configuration, and dashboard controls. Challenge an analysis through analysis chat and carry the reviewed finding into the existing Fix investigation flow.
- **The stopped causal critic is removed.** `agentSandbox.causalCritic` configuration and the causal-critic fetcher and worker flags are no longer accepted. Remove those values before upgrading.
- **`analysisRuntime.type` is removed** from Helm values and the `-analysis-runtime` CLI flag is no longer accepted. Failure analysis always runs in-process. Remove `analysisRuntime` from consumer values before installing or rendering the chart. The guarded upgrade helper strips the stored selector automatically.
- **Presubmit dashboard inclusion has one owner** at `discovery.include_presubmits` in `project.yaml`. The old `source.include_presubmits`, reusable workflow `include-presubmits` input, and Helm `fetcher.includePresubmits` value are removed.
- **The TestGrid selector moved** from `testgrid.dashboard` to `discovery.testgrid_dashboard`, keeping job-discovery policy in one section.
- **`ai.critique.cache_policy` no longer depends on `ai.critique.max_retries`.** An omitted policy previously resolved to advisory with zero retries and strict with any positive value, so raising the repair budget silently switched cache enforcement to the strictest setting. An omitted policy now resolves to `hard`. Set `ai.critique.cache_policy` explicitly if you relied on the old behavior.
- **`resolved.json` gains a `causes` map** and its entries gain a `cause` field, the server adds `POST /api/causes/{signature}/resolve` and `/unresolve`, and `resolve.RemoveMatching` now takes a `*resolve.State`. Existing pattern-scope resolutions keep working.
- **The `truncated` key is removed from `grep_artifact` results**, replaced by `matches_truncated` and `scan_truncated`.
- **The `retained_stale` action eligibility reason is removed.** Anything consuming eligibility reason codes should drop it.
- **Chat-enabled Helm deployments roll the server with `Recreate`** to prevent mixed chat-state writers. A manual deployment with analysis chat enabled must stop old server replicas before starting the new version.
