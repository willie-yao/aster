A follow-up to rc.10 that makes prepared cause findings actually reach the causes a maintainer can open, explains a fix preview that changed nothing, and adds a credential-free way to develop the authenticated dashboard locally.

Upgrading from rc.10 needs no configuration change and forces no re-analysis. The critique contract stays at 11, so cached analyses are reused.

## Fixed

- **Prepared cause findings no longer require an eligible Fix target.** That gate reduced to published file links, which are presentation output rather than a precondition for reading artifacts and forming an evidence-backed finding, so a cause with verified artifact citations but no file links was permanently ineligible even though its cause chat worked normally when opened by hand. Preparation was therefore strictly weaker than the interactive conversation it exists to pre-compute. Candidate ranking also ignored whether a cause was visible, so job iteration order decided where each run's budget went: on a deployment where a non-systemic job sorted first, the entire budget went to causes that render no cause card and the published causes were never reached. Preparation now resolves exactly what an interactive cause conversation resolves and prefers causes on published recurring patterns. Whether a cause can later start a Fix is left to the Fix path, which answers that for itself against fresher state. Preparation remains limited to active patterns, so recovered and verified-fixed causes are still skipped.
- **A fix preview that changed no files is no longer reported as a failure.** That outcome is now distinguished from a runtime error, the coding agent's bounded redacted explanation appears beside the feedback controls, source-verification warnings are labelled separately, and the preview states that the instruction must change before regenerating.
- **The navigation rail reports what a refresh is doing.** An in-progress fetch previously collapsed to a bare spinner, so a stalled pass and a working one were indistinguishable without opening the status popover. The rail now names the active phase, and during artifact fetching and analysis it shows the completed and total counts with a progress bar.

## Added

- **`make dev-mock` runs the authenticated dashboard locally without credentials.** Developing the signed-in UI previously required a model provider, GitHub write access, or a cluster: `make dev` serves no API so the sign-in control, action buttons, analysis chat, and operator pages never rendered, and `make dev-actions` rendered them only from a static build with no hot reload and only with real credentials. The new `server -mock` flag pairs with the Vite dev server, hot reload included. Routes, authentication, CSRF protection, the capability descriptor, and JSON shapes are the production ones; only the work behind them is fabricated. Issue and fix drafting, analysis chat, chat-to-fix, and pull request escalation answer from in-memory fakes, while marking a pattern resolved runs the real code. Populate content first with `make snapshot-data SITE=https://your-dashboard`. See [Local development](../docs/development.md) for the `MOCK_LATENCY`, `MOCK_LOGIN`, `MOCK_HOST`, and `MOCK_PORT` knobs.

  The mock server grants administrator access to anyone who can reach it and must only ever run on a developer machine. It binds loopback by default.

## Changed

- The analysis chat composer, the job detail header, and the analysis briefing no longer strand horizontal space, and the composer's dialogs and actions match the rest of the dashboard. Run-history dots on the overview are larger and easier to hit.

## Accessibility

- The "open representative failure" route button's accessible name now begins with its visible label, so speech input can activate it by what is on screen.
- The chat composer's Send and Cancel buttons keep a 44px target on touch devices.
