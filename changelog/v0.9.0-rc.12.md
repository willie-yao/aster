A small follow-up to rc.11. The collapsed cause control now says what is waiting behind it, so a prepared finding or an existing shared investigation is visible without expanding every cause in turn.

Upgrading from rc.11 needs no configuration change and forces no re-analysis. The critique contract stays at 11, so cached analyses are reused.

## Added

- **The collapsed "Investigate cause" control reports what is waiting.** A cause whose engine-prepared first answer is ready shows "Finding ready", and a cause someone has already opened a shared investigation on shows "Investigated by &lt;login&gt;". Until now these were indistinguishable from a cause with nothing waiting, so the only way to find out was to expand each one, and the only way to confirm preparation was reaching published causes at all was to read `prepared_cause_findings.json` out of the worker's volume by hand.

  The direct fix was unavailable because the sole path that revealed a prepared finding also created a shared session, which would have attributed investigations to whoever happened to load the page first. Server mode instead gains `POST /api/analysis-chat/prepared/lookup`, an authenticated read-only batch check that answers every cause on a page in one request without creating anything.

  The markers are visible only to signed-in operators, and nothing new is written to the published `data/` output, so anonymous visitors see exactly what they saw before. No configuration change is needed; the indicator appears wherever cause chat is already enabled.

## Fixed

- **The "Resolve failure" action stays at the right end of its action bar.** It previously jumped to the left whenever the cause had no fix-eligible test to route to, and whenever a long test name pushed it onto a second row, because the bar positioned it with a rule that anchors a lone control to the start rather than the end. A long test name now stays on one row with the action and truncates with an ellipsis instead of wrapping.
