This release tightens Aster's pre-v1 contracts and removes configuration and runtime paths that no longer have an owner. AI provider coordinates now belong to the deployment, the semantic judge and private shadow analyzer are gone, and private state readers accept only the current schema. Cause investigations gain verified source-code citations, while Responses users gain better prompt-cache routing and complete cache-write usage accounting.

**Upgrading requires configuration changes and forces re-analysis.** The critique contract moves from 11 to 18. Cached analyses are revalidated and run again as they are encountered; no cache-generation change is required.

Before upgrading:

- Remove `ai.api`, `ai.endpoint`, `ai.model`, and `ai.cache_generation` from `project.yaml`. Supply them through workflow inputs, environment variables, or Kubernetes `ai.*` and `analysisCache.generation` values.
- Kubernetes deployments that kept `GITHUB_READ_TOKEN` only in `ai.existingSecret` must set `ai.githubReadTokenSecretName` or `ai.githubReadToken`.
- Remove `ai.semantic_judge`, `ai.responses_websocket`, `agentSandbox.analysisShadow`, `agentSandbox.analyzer`, and other deprecated Helm values rejected by the current schema.
- Expect noncurrent private action, chat, recurrence, and request state to reset under their exact-current schemas. Update API and frontend clients for the breaking response-field changes listed below.
- When updating the independently pinned Agent Sandbox Fix executor, deploy the server first. The executor result adds an optional `provider_error` field that the new server accepts.

## Added

- **Cause investigations can cite the exact source revision tested by a failed build.** Aster resolves the repository revision from Prow metadata, reads the relevant source, and publishes only citations verified against bytes read in the same turn.
- **Cause chat can compare a failure group with the newest later run.** A later pass is reported as non-reproduction evidence rather than proof that a change fixed the cause.
- **Responses usage includes cache creation.** Provider-reported cache-write input tokens are retained separately and can be priced with `cache_write_input_per_million`.
- **Stable prompt-cache routing keys reduce avoidable provider cache misses.** Keys reuse the engine and consumer prompt prefix while separating different Tool schemas.
- **OpenAI Responses deployments can use Flex processing.** Set `ai.service_tier: flex`; Aster rejects Flex for non-OpenAI endpoints and falls back to the automatic tier after repeated capacity shortages.
- **Fix credential failures are actionable.** Sanitized authentication and entitlement errors identify the configured Secret, endpoint, and model, and failed requests can be retried after credentials are corrected.

## Changed

- **Successful analysis disposition is now `citations_verified`.** The old `grounded` value and benchmark boolean are removed. The new name states the property Aster verifies: retained citations match evidence read by the analyzer. It does not claim that every causal conclusion is proven.
- **The semantic judge is removed.** Deterministic critique remains the publication and cache-quality gate without an additional model request or semantic revision round.
- **Recurring-pattern rows prioritize what is failing now.** Current job status, same-cause streaks, rolling reliability, and recovery state are presented as separate signals.
- **The model-quality benchmark is a separate Go module.** Run it with `go -C backend/benchmarks test ./...`; main backend builds and tests no longer compile it. The corpus adds five digest-pinned historical failures and a public kubectl skew fixture, replaces a mixed-cause upgrade case, and accepts audited equivalent diagnoses without accepting contradictory claims.

## Fixed

- Chat Completions with GPT-5.4 and later now rejects an explicit reasoning effort other than `none` during startup instead of allowing every analysis to fail as unavailable. Use Responses or set reasoning effort to `none`.
- Responses analysis preserves assistant phases and forced-finalization state across compaction and replay.
- Evidence-budget overflow keeps citations that still validate against retained artifact text instead of dropping the entire citation set.
- Deterministic critique accepts concrete validation steps such as rebuilding or rerunning after a specific remediation.
- The job detail history strip and runtime chart no longer require horizontal scrolling at normal desktop widths.

## Breaking

- `project.yaml` no longer accepts `ai.api`, `ai.endpoint`, `ai.model`, `ai.cache_generation`, or `ai.semantic_judge`. Provider coordinates and cache generation are deployment-owned. `ai.headers`, analysis policy, usage pricing, and the Fix runtime's `model_provider` remain project-owned.
- Responses WebSocket continuation is removed. Responses requests use HTTP.
- The Agent Sandbox analysis shadow and standalone analyzer are removed, including their commands, images, flags, Helm values, and private state. Authoritative in-process analysis and Agent Sandbox Fix remain supported.
- Authenticated action clients must send schema-exact single JSON values, and frontend clients must consume `ActionEligibility.code` instead of removed compatibility fields.
- The fetcher and worker `-include-presubmits` flag, onboarding `-no-prompt` alias, PAT authentication helpers, local Fix verification path, deprecated Helm values, setup handoff v1, and removed Go aliases are no longer accepted.
- Noncurrent private state versions are rejected or reset instead of being read through compatibility paths.
