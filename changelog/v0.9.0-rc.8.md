## Added

- **The `Image` workflow can be run manually against a branch.** It publishes commit-addressed `sha-<short>` images for the application, remote fixer, and Agent Sandbox Fix executor, so a merged commit can be deployed without cutting a release tag. A manual run against a branch cannot move a release tag, `latest`, or the `vMAJOR` alias. Agent Sandbox configuration still pins the Fix executor by digest, so resolve it after the run finishes.

## Changed

- **Release notes are now one file per release tag.** They have moved out of `CHANGELOG.md` into `changelog/<tag>.md`; the root `CHANGELOG.md` keeps the versioning policy and indexes those files.

  Contributors: every pull request now needs a `release-note` block in its description, checked by CI. Write the note for someone upgrading Aster, and use `NONE` when the change has no effect a user would notice.
- **Analysis briefing sections share one boundary treatment.** Consecutive sections are separated by a rule and 36px rather than 18px of bare whitespace, against the unchanged 6px gap between a section's label and its body, so the boundary between two unrelated sections is no longer read as part of one. Severity is stated once per surface instead of twice within about 100px. The section component existed as byte-identical copies behind the test detail and pattern banner surfaces; both now render the same shared component and cannot drift apart. Presentation only: no published data changed and no new design tokens were introduced.

## Fixed

- **Analysis chat turns died at validation gates and returned an opaque 502.** Roughly a quarter to a half of turns on a live consumer failed this way, and the turns that survived spent several model round trips getting there. The chat agent enforced a stricter evidence contract than the main analyzer while having less machinery to satisfy it, and its gates rejected a turn rather than correcting it.

  Validation is now split into hard failures and soft evidence gates, and a failed gate gets up to one corrective round inside the tool loop. Unparseable JSON, missing or unknown fields, a bad assessment enum, and a malformed `proposed_revision` still fail the turn when they survive that round and no valid answer from an earlier round is available to fall back on. Every per-citation check, the citation cap, and the "a supporting or challenging answer needs citations" rule instead degrade the turn: citations and `proposed_revision` are dropped, the assessment becomes `inconclusive`, and the reply is marked **Unverified** with a closed-enum reason (`citation`, `reference`, `missing`). The single retry used to switch to a finalize-only completion with no tools, so a model that failed to cite an artifact had no way to go read one; there is now one corrective round that stays inside the tool loop with the tool schemas attached and carries the specific failure back to the model.

  Evidence is also conversation-scoped. The evidence index is rebuilt from citations that earlier turns already proved, so a follow-up such as "why did you conclude that?" can cite an artifact read a turn ago instead of re-reading everything or failing outright. Seeding walks newest-first under its own per-path budget, so it cannot crowd out a current-turn read.

  Content that fails a local policy check is no longer reported as a gateway error. A residual hard failure on the plain path returns **422** with the closed-enum gate in the `X-Analysis-Chat-Reason` header and a gate-specific message in the body. A streaming turn has already committed `200 OK` before the model runs, so the same failure arrives as an SSE `error` event carrying `status: 422` and the gate in its payload rather than as an HTTP status or header.

  The evidence-first guarantee is preserved where it matters, with one deliberate relaxation: the previous question-shape heuristic that forced artifact reads for certain questions is gone, and citations are now required only for a `supports` or `challenges` answer, so an `inconclusive` answer can stand uncited and unmarked. An unverified answer renders with a warning border, a filled "Unverified" chip in place of the assessment chip, and a caption naming the gate that failed, and its fix and correction buttons are hidden. An unverified answer can never become a proposed code change, including when it follows a verified turn whose citations it would otherwise have inherited.

  **Breaking (internal Go API).** `ErrCitationValidationFailed` is deleted, since citation failures can no longer be terminal.
- **Fix previews failed with `403 Forbidden` whenever the model provider was GitHub Copilot.** The in-process transport sends a `Copilot-Integration-Id` header to `*.githubcopilot.com` endpoints, but the sandbox executors set no HTTP headers on the OpenCode provider config, so the sandbox called the same endpoint without it and was rejected. Each failure pulled a 138MB image, cloned the repository, and scheduled a VM before the request was refused. The header is now owned by a shared package that both the in-process transport and the sandbox executors depend on, so the two paths can no longer diverge on the same provider. Consumer-supplied extra headers are still merged last and still override.

  The old host match also accepted `notgithubcopilot.com`; the shared helper requires an exact host or a `.githubcopilot.com` suffix. Gateway credential mode is unaffected, and the header value is not a secret, so the credential-free guarantees on executor output are unchanged.
- **A Fix preview rejected for a bad credential was reported as a generic runtime fault.** The executor already had the precise diagnosis in its result payload, but it was discarded before reaching an operator, so recovering it meant re-running the request while tailing the sandbox pod. A provider rejection is now carried structurally: the executor emits a `provider_credential` failure code with a reason naming the HTTP status when the provider supplied one, which maps to a `provider_credential_rejected` reason code on the persisted request, so a permanent credential rejection is distinguishable from a transient fault. Every draft generation failure now reaches a server log line with its reason code, category, and sanitized cause, and the frontend renders an actionable message instead of "failed in the isolated runtime". Regenerating stays unavailable, since it cannot succeed until the credential is fixed. Non-auth failures, including a non-retryable 400 or a 429, deliberately stay classified as runtime faults.
- **Runtime trend chart samples were not reachable.** The dots were bare shapes that were never wrapped in a link, so they could not be clicked; the chart was marked as a single image, which hid the per-dot hover titles; and the band and footer stated the same median, p95, and direction twice. Each sample is now a link to its run with a tooltip and a focus ring, and the duplicated footer is replaced by a legend identifying the two dashed reference lines by their exact dash patterns. Because the run count follows the consumer's `builds:` setting, the chart reserves width per sample and scrolls rather than compressing targets until they overlap, and it opens on the latest run.
