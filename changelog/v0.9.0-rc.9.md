Analysis chat is the headline of this release. Every gate that could reject a good answer was either corrected or made to degrade instead of fail, and the engine now attributes citation quotes itself rather than grading the model's typing. Alongside that, failure recurrence is remembered across build windows, the analyzer no longer stops with planned evidence unread, and causes on the briefing must say what can be done about them.

**Upgrading forces re-analysis.** The critique version moves from 9 to 10, so analyses cached by rc.8 are revalidated and re-run as they are encountered in the fetched build window. No `ai.cache_generation` change is needed for the analysis improvements in this release to reach those failures.

**Breaking:** the analysis traces endpoint, route, and capability flag were renamed to analysis health; `fix_intent` is no longer accepted on chat message requests; and Agent Sandbox values were restructured. See the Breaking section.

## Added

- **Failure recurrence is tracked across build windows.** Causal-group correlation only sees the current window and needs several failures within it before it groups anything, so a test failing once every few weeks never formed a pattern and left no memory behind. Every failed build now contributes to a durable recurrence record whether or not it correlated, and job pages report how long a failure has been recurring, including occurrences that have aged out of the window. History is shown only when it adds something the current window does not already show, and it is described as similar failures rather than a confirmed shared cause. Recurrence accumulates going forward from the first run on this version and cannot be reconstructed for builds that have already left the window.
- **Analysis Health replaces the Analysis Traces page.** The page reported every AI request, and because it was emptied and refilled on each fetch pass it settled into listing analyses where nothing had happened. Cache hits are no longer recorded, the ledger persists across runs as a bounded window of up to 250 fresh analyses, and analyses are grouped by health with a plain-language reason for each failed or degraded one, drawn from the engine's own runtime signals. Runtime detail for a single failure now expands inline on the test detail page.
- **Maintainers can discard an analysis chat and start a new one.** The UI already told maintainers to start a new conversation when a request could not be recovered or the attempt limit was reached, but nothing performed it, and reloading or signing out reattached the same conversation. Because the attempt budget counts failed turns, attempts lost to validation failures meant waiting out the two hour session lifetime. A "New conversation" control now confirms, discards, and starts fresh with a clean budget, and it also stops a turn that is still running. Discarding is irreversible; the published analysis is never affected. Server deployments gain `DELETE /api/analysis-chat/sessions/{id}` behind the same authentication and cross-origin protection as the rest of analysis chat.
- **Pushing to `main` publishes commit-addressed `sha-<short>` images** for the application, remote fixer, and Agent Sandbox Fix executor. Deploying an unreleased main commit previously meant dispatching the `Image` workflow by hand and waiting for it. Release tag behaviour is unchanged, and the Agent Sandbox analysis executor and stager remain manual-only.
- **A private Agent Sandbox analysis-shadow evaluation path** over sealed artifact and source workspaces, with in-process analysis still authoritative. Cross-arm source grounding uses one symmetric content-read range contract and citation capabilities are reported separately.

## Changed

- **Causes on the analysis briefing now show what can be done about them.** A cause could previously be presented with a root cause and no action at all: transient failures reported no fix and nothing rejected a remediation that amounted to re-running the job, causal groups had no field to carry a fix even when their own per-failure analysis had found one, and the remediation investigation refused any cause seen in only one build, permanently excluding deterministic high-confidence bugs. Each cause now displays the suggested fix its own evidence supports, marked unverified and attributed to the build it came from, and a remediation that leaves nothing to act on is rejected and re-prompted unless the analyzer states that the evidence supports no fix. A cause whose fix belongs to a dependency always names that repository. The status row is now "Verified fix investigation" rather than the generic "Remediation", because it reports one mechanism and the other routes stay open when it cannot run. Cached analyses are revalidated against the stricter contract, so expect re-analysis on the next run after upgrading.
- **Failure analysis no longer stops with planned evidence unread.** The analyzer could read one relevant artifact group, decide it had enough, and publish while another group sat unread in the same build, because the investigation floors measured only effort in tool calls and fetched bytes. The ranked evidence plan is now tracked for the whole investigation: every tool result reports which required groups are still unread, and an answer that leaves available evidence unconsulted sends the model back with the specific groups and candidate paths named. This is bounded by progress, a small attempt limit, and the time, context, and byte budgets, and evidence that does not exist in a build never reopens the loop. No quality gate was relaxed: analyses that still end with evidence unread publish as preliminary with the same warning as before.
- **A transient verdict no longer dead-ends without a remediation.** Once a failure was classified transient the analyzer stopped investigating and discarded any fix it had already found, leaving a causal group whose text named a real, fixable defect that the dashboard offered no way to act on. The verdict now answers only whether a rerun is likely to pass, not whether anyone can act. Infrastructure flake is still never reclassified as a real bug, but a durable resilience improvement the evidence already shows, such as a missing retry or backoff on a retryable status, a wait budget shorter than the observed duration, or a missing readiness guard, is now reported and attributed to the repository that owns it. Cached analyses from rc.8 are revalidated on upgrade, so this reaches existing failures without a `ai.cache_generation` change.
- **The analysis chat has no separate Fix investigation mode.** There is one conversation: ask questions, and any answer with verified citations can start a fix proposal without discarding the conversation to switch modes. Asking a question no longer depends on source verification, and every fix proposal now pins its source revision and verified file hashes, which previously happened only for turns started from the removed mode.
- **Analysis chat and fix-proposal surfaces match the rest of the dashboard.** They carried their own visual language: rounded corners against the squared detail page, bordered pill chips around read-only timings, and amber buttons on every step of the fix flow. Amber carries CI status meaning in Aster, so using it for ordinary actions made opening a dialog look as consequential as opening a pull request. Amber is now reserved for actions that write to GitHub, timings render as monospace text like every other metric, and dialogs wear the same section band as the page that opened them. The shared corner radius moved from 6px to 4px, which affects the whole interface because most surfaces already overrode the old value locally. Markdown bold in analysis text now renders as bold instead of showing the asterisks verbatim, and tinted status chips that measured 4.04:1 against the WCAG AA minimum of 4.5:1 now clear the threshold in both light and dark modes.

## Fixed

- **Analysis chat no longer discards a usable answer because of how it was formatted.** An answer the engine could not parse as its response contract, including one where the model simply replied in prose, was thrown away and the maintainer saw "Response validation failed" with no answer at all. Such a response is now returned marked unverified, the same way an unverifiable citation already was. A completely empty response still fails the turn, as does one that only announces a next step without concluding. Unverified answers still cannot start a fix preview or a correction.
- **Citation quotes are attributed by the engine instead of graded against the model's typing.** A quote tells the engine which passage the answer means; the engine finds that passage in what the artifact tools actually returned and stores its own copy. An accurate quote is no longer marked unverified for re-wrapping a log line, dropping the indentation or the colour escape codes that Prow build logs carry in volume, and the quote a maintainer reads is guaranteed to be real tool output. The per-quote limit is raised from 1000 to 2000 bytes. A quote so short or generic that it could mean several passages is reported unverified, as is a passage too long to record, and a rejected quote is told what was wrong with it so the corrective round can repair it. Because an unverified answer cannot start a fix proposal, these false rejections were hiding the fix option on good answers. The analyzer's own citation checks use the same rule, so an analysis citation that dropped colour codes now verifies too.
- **Analysis chat no longer presents the model's announcement of its next step as the answer.** A model that wrote "let me now look at the deletion window:" and then called no tool produced a tools-free turn, which the engine treated as final and salvaged. Salvage now declines content that trails off without concluding, a turn gets two corrective rounds instead of one, and a turn that only announced a step is told so and must either make that call or answer now. The extra corrective round applies to every response gate, so a turn that has to be corrected costs one more model round than before.
- **Analysis chat could exhaust its evidence budget partway through a large artifact** and respond by telling itself to stop reading rather than to read less, leaving the turn with nothing to cite. Context-window detection never worked against GitHub Copilot endpoints, which report limits under `capabilities.limits` rather than the fields the engine decoded, so every model appeared to have no reported window; detection now reads those fields and prefers the prompt-token ceiling over the total window, since a model's prompt share of its window varies from half to nearly all. The per-artifact cap was a fixed 128 KB regardless of the model's actual room and is now derived from the configured context budget. A read that still does not fit is told how many bytes remain so it can retry narrower. Deployments that set an explicit context window override can drop it after upgrading.
- **Fix proposal failures explain themselves.** A failure that showed one generic regeneration message now reports whether the coding agent returned no repository change or exceeded the allowed review scope, and regeneration guidance follows that diagnosis instead of always claiming a maintainer instruction will help. Source-finding warnings name the unresolved identifiers and recognise verified struct fields, so a finding referencing a real struct field is no longer reported as ungrounded.
- **A guessed citation key no longer fails a turn.** The tool-loop prompt shows the full citation object rather than an empty array, and a decode failure names the expected keys and types instead of returning an unactionable "response is not valid analysis-chat JSON" that the corrective round could not repair.
- **Chat failure logs name the specific validation rule a turn tripped**, in a `validation_detail` field alongside the existing `validation` category, so a failure like `response_contract` can be diagnosed from the server instead of guessing among the rules that category covers.
- **The analysis chat panel no longer traps the scroll wheel.** The message list opted out of scroll chaining with `overscroll-behavior: contain`, so scrolling up inside a conversation stopped at the top of the list instead of continuing to the page behind it. Auto-scrolling to new messages is unchanged.
- **The Agent Sandbox analysis executor and stager recorded an image tag that did not exist in the registry.** Both publish under a short commit-addressed tag such as `sha-5caeac3` but were built with the full 40-character commit SHA baked in as their identity, surfacing through the `io.prow-ai-dashboard.image-tag` label and the binary's `--version` output, so a running container could not be traced back to its image. The application, remote-fixer, and fix-executor images were already correct.
- **Dashboard navigation reflows cleanly at laptop and mobile widths** instead of overlapping or hiding destinations. Mobile search, AI analysis details, cost charts, and trace views present context and empty states more clearly, and stale fix routes and passing-run filters no longer imply unavailable actions or empty results.
- **The analysis chat reads as a section of the detail page** rather than a separate widget embedded in it. Its header wears the same section band as Run history and Runtime trend, containers are squared to the page radius, and the maintainer's own turn is marked with a violet left accent rather than an asymmetric chat bubble. The panel title is a real heading that wraps its expand toggle rather than sitting inside the button, which screen readers announced inconsistently.

## Breaking

- **The analysis traces surface is now analysis health.** The endpoint moved from `/api/analysis-traces` to `/api/analysis-health` and its download from `/api/analysis-traces/download` to `/api/analysis-health/download`, with the attachment now named `analysis-health.json`. The capability flag moved from `analysis_traces` to `analysis_health`, and the route from `/analysis-traces` to `/analysis-health`. Download automation pinned to the old path breaks.
- **`fix_intent` is no longer accepted on analysis chat message requests.** It selected the removed Fix investigation mode. Because the request decoder rejects unknown fields, a client still sending it now receives HTTP 400 instead of having it ignored.
- **Agent Sandbox values were restructured.** Under `agentSandbox.analysisShadow`, the `agentVersion`, `retries`, and `maxTurns` keys were removed, and `stagerImage`, `dashboardImage`, `input`, `maxSteps`, `modelContextTokens`, `modelOutputTokens`, `requireSourceEvidence`, and `quota` are required. An enabled `agentSandbox.analyzer` now also requires `stagerImage`. Schema validation applies to the whole values file, so a deployment that still carries the removed keys fails validation even with these features disabled. Enabled shadow deployments must additionally set `networkPolicy.mode` to `cilium`; the `kubernetes` mode that rc.8 accepted is now rejected.
